=====================================================================================================================
  VORTEX ENGINE - WHAT LUA AND HSCRIPT (.hx) CAN DO THAT ONLY VORTEX HAS
=====================================================================================================================
Only what Vortex Engine adds is here. Everything from Psych Engine 1.0.4 (Lua and HScript) and from V-Slice (.hxc scripts,
Polymod) works as on their own wikis and is not repeated.

In HScript, "game" is the PlayState (the same as PlayState.instance). Every "setProperty('name', value)" below is
"game.name = value;" in HScript.


//------------------------------------------------------------------------------------------------------------------//
  1. KNOWING THE SCRIPT IS RUNNING ON VORTEX ENGINE
//------------------------------------------------------------------------------------------------------------------//
LUA:
    function onCreate()
        if VortexEngine then
            -- Vortex Engine
        else
            -- Psych Engine or another fork (VortexEngine is nil there)
        end
    end

HScript/Hx:
    function onCreate() {
        var isVortex = false;
        try {
            if (VortexEngine == true) isVortex = true;
        } catch(e) {
            // (on other engines the variable doesn't exist and reading it is an error)
            isVortex = false;
        }

        if (isVortex) {
            // Vortex Engine
        } else {
            // Psych Engine or another fork
        }
    }


//------------------------------------------------------------------------------------------------------------------//
  2. VARIABLES (Lua globals; in HScript the same names, or game.xxx)
//------------------------------------------------------------------------------------------------------------------//
VortexEngine     // Bool - always true on Vortex Engine (Lua and HScript)
playAsOpponent   // Bool - (Lua) "Play as Opponent" is on: the player is hitting the opponent's notes.
                 //        The health scripts get (getProperty('health'), getHealth...) is still Boyfriend's, as songs
                 //        are made, except before the song starts (the health it starts with is the player's) and in
                 //        noteMiss / noteMissPress (what's taken on a miss is the player's). Losing shows the opponent
                 //        fading away in the color of its icon (or its own "firstDeath" animation, if it has one).
                 //        HScript: game.playAsOpponent
                 //        The sides of the chart don't change: mustPress / goodNoteHit are still the right side's notes,
                 //        and they're played by the computer. See "playable" in section 5.
onlinePlay       // Bool - the song is an online match of Vortex's multiplayer (Lua and HScript)
onlineHost       // Bool - an online match, and this player is the one hosting it (Lua and HScript)

Online and the countdown: if a script stops the countdown (onStartCountdown returning Function_Stop: a dialogue, a cutscene,
a loading screen that waits for ENTER) and starts it later with startCountdown(), the two players wait for each other again
and the song starts at the same time for both. Nothing has to be done in the script for it.

Example (Lua) - a mechanic that would be unfair online:
    function onCreatePost()
        if onlinePlay then
            close() -- turns this script off for online matches
        end
    end


//------------------------------------------------------------------------------------------------------------------//
  3. FUNCTIONS (Lua). HScript: call the same ones on "game" (game.setLaneUnderlay(true, 0.7);)
//------------------------------------------------------------------------------------------------------------------//
setLaneUnderlay(show, alpha)    // Bool, Float (optional, 0 to 1, 0.5 if not given)
                                // Turns the dark lanes under the player's notes ("Lane Underlay") on or off and sets how
                                // dark they are, whatever the player's option says. Works at any time of the song.
                                //     setLaneUnderlay(true, 0.8)   setLaneUnderlay(false)
                                // HScript: game.setLaneUnderlay(true, 0.8);  game.laneUnderlayAlpha = 0.3;

setScoreCamera(where)           // String: "game" or "hud"
                                // Where the ratings ("Sick!"), the combo numbers and "Combo" pop up: in the scene (they
                                // move and zoom with the stage) or on the HUD. The player's option is only the default.

setHiddenNotes(hide)            // Bool
                                // Hides every note, the ones already on the screen too ("Hidden Notes" gameplay changer),
                                // or shows them again. Hit them by memory!

getTallies()                    // returns a table: sick, good, bad, shit, missed, combo, maxCombo, totalNotesHit, totalNotes
                                // What the V-Slice style results screen counts, so far in the song.
                                //     local t = getTallies()
                                //     debugPrint('Sicks: ' .. t.sick .. ' / ' .. t.totalNotes)
                                // HScript: var t = game.getTallies(); trace(t.sick);

startConversation(name)         // String - returns true if it was found
                                // Shows a V-Slice dialogue (data/dialogue/conversations/NAME.json of the mod) in a Psych
                                // song. Like startDialogue: call it in onStartCountdown (return Function_Stop) or onEndSong,
                                // and the song starts (or ends) when the dialogue is over.
                                // HScript: game.startConversation('name', function() { ... }); (the function runs at the end
                                // instead of starting the song)

setBlendMode(tag, mode)         // (Psych's function, with more modes on Vortex)
                                // "overlay", "hardlight", "difference" and "invert" now really work on Lua sprites
                                // (makeLuaSprite / makeAnimatedLuaSprite), drawn the way V-Slice's cameras do them.
                                //     makeLuaSprite('light', 'stage/light', 0, 0)
                                //     setBlendMode('light', 'overlay')
                                //     addLuaSprite('light', true)
                                // HScript: use a psychlua.ModchartSprite (import psychlua.ModchartSprite;), set
                                // sprite.cameraBlends = true; and sprite.blend = BlendMode.OVERLAY (import openfl.display.BlendMode;)


//------------------------------------------------------------------------------------------------------------------//
  4. NEW SCRIPT EVENTS (callbacks the engine calls on Lua and HScript)
//------------------------------------------------------------------------------------------------------------------//
function onBreakStart(seconds)     // a part of the song with 3 seconds or more without notes to hit started;
                                   // "seconds" is how long it is (in real seconds, playback rate included).
                                   // Called even if the player turned the break timer off.
function onBreakEnd()              // the notes are coming again (or the song ended)
function onConversationEnd(name)   // a V-Slice dialogue started with startConversation ended

Example (Lua) - zoom out during the breaks:
    function onBreakStart(seconds)
        doTweenZoom('breakZoom', 'camGame', 0.7, 1, 'quadOut')
    end
    function onBreakEnd()
        doTweenZoom('breakZoom', 'camGame', getProperty('defaultCamZoom'), 0.5, 'quadIn')
    end


//------------------------------------------------------------------------------------------------------------------//
  5. PROPERTIES (setProperty / getProperty in Lua, game.xxx in HScript)
//------------------------------------------------------------------------------------------------------------------//
Each one starts with the player's option and can be changed at any time of the song.

setProperty('iconBop', false)         // Bool - the health icons bop on the beat
setProperty('sustainWiggle', false)   // Bool - the long notes wiggle (needs Shaders on)
setProperty('showBreakTimer', false)  // Bool - the countdown that shows up when there are 3 seconds or more without notes
setProperty('ghostNotes', true)       // Bool - two notes of the same character together (35 ms apart) leave an
                                      //        afterimage of the first pose
setProperty('healthDrain', 1)         // Float, 0 to 2 - every note the opponent hits takes health (0.1 x this per note,
                                      //        a little per piece of a long note). It never kills: health stops at 0.01
setProperty('speedMiss', true)        // Bool - every miss makes the song 5% faster, up to 2x
setProperty('hiddennotes', true)      // Bool - notes that show up from now on are invisible (setHiddenNotes also hides
                                      //        the ones already there)
setProperty('showLaneUnderlay', true) // Bool - shows/hides the lanes; use setLaneUnderlay to turn them on when the
                                      //        player's option is off (they have to be made first)
setProperty('laneUnderlayAlpha', 0.5) // Float, 0 to 1 - how dark the lanes are

Read only (getProperty):
getProperty('isResting')              // Bool - a break (see onBreakStart) is going on
getProperty('maxRestTime')            // Float - how long the current/last break is, in seconds
getProperty('maxCombo')               // Int - the biggest combo of the song
getProperty('scoreCamera')            // String - "Game" or "HUD" (change it with setScoreCamera)
getProperty('isVSliceStage')          // Bool - the stage is a V-Slice stage (from a V-Slice mod)
getProperty('playableCharacter.curCharacter')  // the character the player is playing (boyfriend, or dad with Play as
getProperty('otherCharacter.curCharacter')     //   Opponent) and the one singing by itself

Objects of Vortex's own things, to move, recolor or hide like any other sprite:
'restCountdownTxt'     // the text of the break timer ("5s")
'restTimerBar'         // its bar
'restportrait'         // its picture
    setProperty('restCountdownTxt.color', getColorFromHex('FF66CC'))
    setProperty('restTimerBar.y', 600)
'laneUnderlays'        // the 4 lanes (a group): setPropertyFromGroup('laneUnderlays', 0, 'color', getColorFromHex('220033'))
'camSus'               // the camera the long notes are on (between the game's and the HUD's)
'camLanes'             // the camera of the lanes (under camSus; null until the lanes are made)
'susWiggle'            // the wiggle of the long notes: setProperty('susWiggle.waveAmplitude', 0.15)
                       //   also waveFrequency, waveSpeed
'grpHoldCovers'        // the sparks on the receptors while a long note is held (V-Slice's hold covers)
'onlineStatsTxt'       // online: the other player's name, score, misses and accuracy, in the bottom corner of their side,
                       //   and who's ahead (null when not online): setProperty('onlineStatsTxt.visible', false)
                       //   How the match is won: getPropertyFromClass('backend.NetworkManager', 'winCondition')
                       //   ("score", "misses" or "accuracy")

Notes (getPropertyFromGroup('notes', i, ...) / note.xxx in HScript):
'playable'             // Bool - this note has to be hit by the player. Same as mustPress, except with Play as
                       //        Opponent on (then it's the opponent's notes). Use it for "the player's notes".

Health icons ('iconP1' / 'iconP2'):
'autoUpdate'           // Bool - false stops the game from placing and bopping the icon, to put it somewhere else
'isAnimated'           // Bool - (read) the icon is an animated one (see section 7)
'hasWinningIcon'       // Bool - (read) the icon has a winning look
    HScript: game.iconP1.autoUpdate = false; game.iconP1.playAnimation('winning'); // "idle", "losing", "winning"

Player's options (read only): getPropertyFromClass('backend.ClientPrefs', 'data.NAME')
    ghostNotes, breakTimer, iconBop, sustainWiggle, laneUnderlay, holdCovers, scoreCamera ("HUD"/"Game"),
    smoothHealthBar, songCredits, resultsScreen, stickerTransition, freeplayStyle ("Standard"/"V-Slice"),
    naughtyness, windowMode ("Windowed"/"Fullscreen"), sharpness
Gameplay changers of Vortex: getPropertyFromClass('backend.ClientPrefs', 'data.gameplaySettings')... or in HScript
    ClientPrefs.getGameplaySetting('healthdrain') / ('hiddennotes') / ('speedmiss')


//------------------------------------------------------------------------------------------------------------------//
  6. HSCRIPT ONLY
//------------------------------------------------------------------------------------------------------------------//
FlxColor has more on Vortex:
    FlxColor.fromString('0x80FF0000')         // "0xAARRGGBB" and "#RRGGBB" read right (with alpha too)
    FlxColor.interpolate(color1, color2, 0.5) // a color between two others (0 = the first, 1 = the second)
    FlxColor.gradient(color1, color2, 10)     // a list of 10 colors from one to the other
    FlxColor.multiply(a, b) / FlxColor.add(a, b) / FlxColor.subtract(a, b)

game.playableCharacter / game.otherCharacter   // Character - the one being played and the one singing by itself
game.playableStrums / game.otherStrums         // the receptors of each, whoever is playing
game.getTallies()                              // see section 3
game.makeStrumsEarly();                        // in onCreatePost: makes the receptors now instead of at the countdown,
                                               // to move them around before the song (they still show up with it)
game.conversation                              // the V-Slice dialogue on the screen (null if none)


//------------------------------------------------------------------------------------------------------------------//
  7. OTHER THINGS MODS CAN USE (no script needed)
//------------------------------------------------------------------------------------------------------------------//
Animated health icons: put an .xml next to the icon's .png (images/icons/NAME.png + NAME.xml) with the animations
    "normal", "losing" and "winning" (by prefix, 24 fps, looped).
Winning icons: an icon image with 3 frames side by side (normal, losing, winning) instead of 2.
Mouse cursor: an image at images/cursor.png (the game's or a mod's: the mod being played comes first) is the cursor on every
    screen. images/cursor.txt next to it, optional: "scale, x, y" - its size and the pixel that clicks ("2, 0, 0", "1, 16, 16").
    Scripts can still change it at any time with FlxG.mouse.load(...): it's set again on the next screen.
Camera angle: turning a camera (setProperty('camGame.angle', 10) / camHUD) no longer leaves empty corners - scripts
    like "zCameraFix" aren't needed anymore.
Play as Opponent and V-Slice scripts: what V-Slice scripts know as "playerStrumline" is the side being played and
    "opponentStrumline" the one the computer plays, so a mod that hides or fades "the opponent's notes" doesn't hide the
    ones the player has to hit. If a song hides the whole HUD while the player has notes coming, it shows up until they're played.
Psych songs and V-Slice songs share the results screen, the sticker transition and the Freeplay menus (options of the
    player), so a Psych mod gets them without doing anything.


//------------------------------------------------------------------------------------------------------------------//
  8. EXTRA CHARACTERS (more characters singing in a song, no script needed)
//------------------------------------------------------------------------------------------------------------------//
On the chart editor, the "Extras" tab adds characters besides the opponent, the player and the girlfriend. Each one has:
    Tag        the name notes and scripts know it by ("pico2")
    Side       Opponent, Player or Girlfriend: whose notes it can sing, and whose spot it stands next to
    Character  the character file
    X / Y      where it stands, from the spot of the main character of its side
    Sings every note of its side (duet) / Behind the main character
Each extra character gets a field of 4 columns of its own on the grid, after the opponent's (up to 4 of them; the columns
get narrower to fit): a note put on it is a note of its side (the player's or the opponent's lanes - a girlfriend's extra
uses the opponent's) that only it sings. Dragging notes from one field to another changes who sings them. The same note on
two fields at the same time is one note in the game, sung by both.
Who sings each note can also be picked on the Note tab, "Sung by":
    Default               the main character of the side (and the extra ones set to sing every note)
    Main character only   only the main one
    Everyone on its side  the main one and every extra one of that side
    (a tag)               only that extra character
They dance on the beat, sing, hold long notes and miss like the main ones (also online and with Play as Opponent).

In the chart (Psych format): a "vortexCharacters" list, and the 5th value of a note says who sings it:
    "vortexCharacters": [{"tag": "pico2", "character": "pico", "side": "opponent", "x": -250, "y": 0,
                          "singsAll": false, "behind": true}]
    [1200, 5, 0, "", "pico2"]      // "main", "all", a tag, or tags separated by commas ("main,pico2")

Scripts get each one by its tag, like a Lua sprite:
    setProperty('pico2.alpha', 0.5)
    playAnim('pico2', 'hey', true)
    getProperty('pico2.curCharacter')
"Change Character" event with the tag as its first value changes that extra character (value 2: the new character).
Notes: getPropertyFromGroup('notes', i, 'singers') / note.singers (HScript) - who sings it (null = the default ones).
HScript: game.extraCharacters (a list: .tag, .side, .char), game.getExtraCharacter('pico2').char

Other engines don't have them: the extra characters don't show up there and the main characters sing every note.


//------------------------------------------------------------------------------------------------------------------//
  9. MAKING A MOD FOR OTHER ENGINES TOO
//------------------------------------------------------------------------------------------------------------------//
The mods menu has a "CHECK MOD" button: it reads the mod's scripts, charts and icons and lists everything it uses that only
Vortex Engine has (everything in this file), with the file and line of each one:
    ERROR       other engines stop the script there (a function only Vortex has)
    DIFFERENT   it works differently or not at all there (callbacks, properties, blend modes, extra characters)
    NOTE        usually fine (a variable that is just nil there, an option that reads as nothing)
A mod with no ERROR or DIFFERENT should also work on Psych Engine 1.0.4 (or V-Slice, for V-Slice mods). Checking the
VortexEngine variable before using something (section 1) is how a script can work on both.


//------------------------------------------------------------------------------------------------------------------//
  10. EVENTS OF VORTEX ENGINE (on the chart editor's event list, no script needed)
//------------------------------------------------------------------------------------------------------------------//
Values with more than one part are separated by commas ("FF0000, 1.5"). Eases are the ones of Lua's tweens (quadOut,
sineInOut, ...). A mod with a custom event of its own with one of these names keeps using its own.
Flash Camera     V1: color, duration (FFFFFF, 1)           V2: camera: game, hud or other (game)
                 (off when the player turned off Flashing Lights)
Fade Screen      V1: color, alpha 0-1 (000000, 1)          V2: duration, ease (1, linear)
                 a color over the whole screen: "000000, 1" fades to black, ", 0" back
Set Camera Zoom  V1: zoom (blank: the stage's)            V2: duration, ease (blank: at once)
Fade HUD         V1: alpha 0-1 (1)                         V2: duration, ease (0.5, linear)
Cinematic Bars   V1: size in pixels (100; 0 takes them away) V2: duration, ease (0.5, linear)
Lyrics           V1: text (blank clears it, \n = new line) V2: color (FFFFFF)
Camera Target    V1: dad, bf, gf or the tag of an extra character (blank: follows the sections again)
Camera Bop       V1: beats between bops (blank: each section, 0: none)   V2: how strong (1)
Character Trail  V1: dad, bf, gf or the tag of an extra character        V2: color (blank removes the trail)
Notes Fade       V1: player, opponent or both              V2: alpha, duration, ease (0, 0.5, linear)
Camera Angle     V1: game, hud or other                    V2: angle, duration, ease (0, 0, linear)
Scripts still get them on onEvent, like any other event.


//------------------------------------------------------------------------------------------------------------------//
  11. STATE SCRIPTS (the game's screens: menus, the loading screen...) - folder "states"
//------------------------------------------------------------------------------------------------------------------//
(The full guide, with more examples: docs/STATE_SCRIPTS.md. A template: docs/scripts/StateTemplate.hx)
HScript files (.hx) in a "states" folder, named after the screen they're for, run on that screen:
    mods/My-Mod/states/MainMenuState.hx      (only while My-Mod is the mod being played, or if it runs globally)
    mods/states/TitleState.hx                (for every mod)
    states/Global.hx                         runs on every screen
Some names: TitleState, MainMenuState, StoryMenuState, FreeplayState, FreeplayStateVslice, CharacterSelectState,
CreditsState, OptionsState, ModsMenuState, LoadingState, ResultsState, GalleryState, MultiplayerMenuState,
AchievementsMenuState (stateName says the one you're on). Songs (PlayState) keep their own scripts folders.

"game" (and "state") is the screen: its things are reached by their names, add() / insert() / remove() work on it.
Callbacks:
    onCreate()                  before the screen makes its things
    onCreatePost()              after it made them (hide, move or replace them here)
    onUpdate(elapsed) / onUpdatePost(elapsed)
    onStepHit() / onBeatHit()   with the menu music (curStep / curBeat)
    onOpenSubState(name) / onCloseSubState()
    onDestroy()                 the screen is being left
Functions:
    switchState('MainMenuState')   goes to a screen by its name (or one the script made)
    resetState()
    debugPrint(text, color)        shows a line on the screen (errors of these scripts show up the same way)
    parseJson(text)                reads JSON text (haxe.Json can't be imported by scripts)
    sharedData                     an object kept from one screen to the next (and for the song's scripts:
                                   getPropertyFromClass('psychlua.StateScripts', 'sharedData.name') in Lua)

LOADING SCREEN (states/LoadingState.hx):
    onLoadingProgress(loaded, total, percent)   something more was loaded (percent from 0 to 1)
    onFinishedLoading()                         everything is loaded: return Function_Stop to keep the screen on,
                                                then call finishLoading() to go on to the song
    hideLoadingScreen(hideBar)                  hides the screen's own picture (and the bar, if true)
    The bar is "bar" (and "barGroup"), the loaded and total things are LoadingState.loaded / LoadingState.loadMax.
Example - a loading screen that shows for at least 2 seconds:
    var txt:FlxText;
    var shown:Float = 0;
    var waiting:Bool = false;
    function onCreatePost() {
        hideLoadingScreen(false);
        txt = new FlxText(0, 330, FlxG.width, 'Loading...', 40);
        txt.alignment = 'center';
        add(txt);
    }
    function onLoadingProgress(loaded, total, percent) {
        if (txt != null) txt.text = 'Loading ' + Math.floor(percent * 100) + '%';
    }
    function onFinishedLoading() {
        if (shown < 2) { waiting = true; return Function_Stop; }
        return Function_Continue;
    }
    function onUpdate(elapsed) {
        shown += elapsed;
        if (waiting && shown > 2) { waiting = false; finishLoading(); }
    }
(Psych's data/LoadingScreen.hx still works too.)


//------------------------------------------------------------------------------------------------------------------//
  12. MORE LUA FUNCTIONS (cameras, camera shaders, the window, notes and characters during the song)
//------------------------------------------------------------------------------------------------------------------//
HScript doesn't need these: it reaches the same things directly (FlxG.cameras, FlxG.stage.window, game.spawnNote(...),
game.addExtraCharacter(...), game.removeExtraCharacter(...)).

CAMERAS
makeLuaCamera(tag, above)       // String, String (optional: "game", "hud", "other" or another camera's tag; "hud" if not
                                // given). A camera of the script's own, right over that one. Sprites go on it with
                                // setObjectCamera(sprite, tag), and it's changed and tweened by its tag like the song's:
                                //     makeLuaCamera('camBG', 'game')        -- between the stage and the HUD
                                //     setObjectCamera('fog', 'camBG')
                                //     setProperty('camBG.zoom', 1.2)
                                //     doTweenZoom('fogZoom', 'camBG', 1, 2, 'quadOut')
removeLuaCamera(tag)            // takes it out (and what's on it stops being drawn). The song's own cameras can't be removed.
luaCameraExists(tag)            // Bool

SHADERS ON A WHOLE CAMERA (the ".frag" files of "shaders/", the same ones setSpriteShader uses)
addCameraShader(camera, shader, tag)   // camera: "game", "hud", "other" or a makeLuaCamera tag. tag (optional, the shader's
                                       // name if not given) is what its values are set by, with the usual functions:
                                       //     addCameraShader('game', 'chromatic', 'chroma')
                                       //     setShaderFloat('chroma', 'amount', 0.005)
                                       // A camera can have more than one; they're applied in the order they were added.
                                       // Does nothing (returns false) when the player turned Shaders off.
removeCameraShader(camera, tag)        // the one with that tag; with no tag, every shader of that camera
tweenShaderFloat(tweenTag, shaderTag, property, value, duration, ease)
                                       // changes a float of a shader smoothly (a sprite's shader too, by the sprite's tag).
                                       // onTweenCompleted(tweenTag, shaderTag) at the end; cancelTween(tweenTag) stops it.
                                       //     tweenShaderFloat('chromaOut', 'chroma', 'amount', 0, 0.5, 'quadOut')

THE GAME'S WINDOW (whatever a song changes is put back when the song is left)
setWindowTitle(text) / getWindowTitle()
setWindowPosition(x, y)  getWindowX()  getWindowY()       // not while the game is fullscreen (returns false)
setWindowSize(width, height)  getWindowWidth()  getWindowHeight()
getScreenWidth()  getScreenHeight()                       // the monitor the window is on
isWindowFullscreen()
windowAlert(message, title)       // a message box of the system; the game waits until it's closed
Example - the window shakes on every beat of a part of the song:
    local baseX, baseY
    function onSongStart() baseX = getWindowX(); baseY = getWindowY() end
    function onBeatHit()
        if curBeat >= 64 and curBeat < 96 then
            setWindowPosition(baseX + getRandomInt(-15, 15), baseY + getRandomInt(-15, 15))
        elseif curBeat == 96 then
            setWindowPosition(baseX, baseY)
        end
    end

NOTES DURING THE SONG
spawnNote(time, column, mustPress, holdLength, noteType, singers)
                                // A note like the chart's: time in milliseconds of the song, column from 0 to
                                // getKeyCount() - 1, mustPress true for the right side's (the player's), holdLength in
                                // milliseconds (0: not a long note), noteType (optional, '' is a normal note), singers
                                // (optional, who sings it: "main", "all" or extra characters' tags, see section 8).
                                // A note added for a time that already went by comes as a miss. Note types with a script
                                // must already be in the song's chart to have their script loaded.
                                //     -- 4 notes, one per column, half a second apart, 2 seconds from now
                                //     for i = 0, 3 do
                                //         spawnNote(getSongPosition() + 2000 + i * 500, i, true)
                                //     end
getKeyCount()                   // how many arrows each side has: 4 on most songs, 1 to 9 on songs with extra keys

EXTRA CHARACTERS DURING THE SONG (the same as the chart's, see section 8)
addExtraCharacter(tag, character, side, x, y, singsAll, behind)
                                // side: "opponent" (default), "player" or "gf". x / y: from the spot of the main
                                // character of that side. singsAll: sings every note of its side. behind: behind the
                                // main character. False if the tag is already used or the character doesn't exist.
                                //     addExtraCharacter('backup', 'pico', 'opponent', -300, 0, true)
                                //     playAnim('backup', 'hey', true)
removeExtraCharacter(tag)       // takes it out of the song
getExtraCharacters()            // a table with the tags of every extra character of the song

CLIPBOARD
setClipboard(text) / getClipboard()


//------------------------------------------------------------------------------------------------------------------//
  13. 3D (sprites, receptors, notes and cameras turned in 3D, and .obj models)
//------------------------------------------------------------------------------------------------------------------//
Everything is seen in perspective from the center of the screen. Angles are in degrees.

SPRITES, RECEPTORS AND NOTES: three new properties
    angleX    turned forward/back (around the horizontal line through its origin)
    angleY    turned left/right (around the vertical line through its origin)
    z         pushed away from the screen (it gets smaller toward the center); negative brings it closer
"angle" still turns it on the screen as always. They work on Lua sprites (makeLuaSprite / makeAnimatedLuaSprite), on the
receptors and on the notes:
    setProperty('card.angleY', 45)
    startTween('cardSpin', 'card', {angleY = 360}, 2, {ease = 'quadInOut'})
    setPropertyFromGroup('playerStrums', 0, 'angleX', 60)
    setPropertyFromGroup('opponentStrums', 2, 'z', 400)
Notes copy them from their receptor (long notes too). To turn a note on its own: setPropertyFromGroup('notes', i, 'copy3D',
false) and then its own angleX / angleY / z.
HScript: sprite.angleY = 45; game.playerStrums.members[0].z = 300;

WHOLE CAMERAS (a shader on the camera: needs the Shaders option on)
setCamera3D(camera, angleX, angleY, z)     // "game", "hud", "other" or a makeLuaCamera tag. All 0: back to normal.
                                           //     setCamera3D('hud', 30, 0, 0)    -- the HUD leans back, notes included
getCamera3D(camera)                        // a table: angleX, angleY, z
tweenCamera3D(tag, camera, angleX, angleY, z, duration, ease)
                                           // little by little; onTweenCompleted(tag, camera) at the end, cancelTween(tag) stops it
                                           //     tweenCamera3D('lean', 'hud', 0, 25, 0, 1, 'quadOut')
The HUD's long notes are on cameras of their own and turn with it.

PERSPECTIVE
setPerspective(distance)        // how far the eye is from the screen, in pixels (1000 if not changed). Smaller: stronger
                                // perspective. Applies to everything above and to the models.

.OBJ MODELS
makeLuaModel(tag, model, texture, x, y)
                                // model: "models/NAME.obj" of the mod (just "NAME" works). texture (optional): an image of
                                // "images/", painted with the model's texture coordinates (without one it's plain white, which
                                // "color" tints). x / y: where its center goes. Made to be 200 pixels on its biggest side.
                                // Then addLuaSprite(tag, true), setObjectCamera, removeLuaSprite... like a sprite.
Its properties (setProperty / startTween):
    x, y, z, angleX, angleY, angle, alpha, color, visible, scrollFactor
    modelScale     pixels per unit of the model
    lighting       true: each triangle is shaded by how much it faces the light (false: flat texture)
    ambient        how dark the side away from the light gets, 0 to 1 (0.35)
    cullBack       true: triangles facing away aren't drawn (turn it off for open or flat models)
    triangleCount  (read only)
Example - a spinning model in the stage:
    function onCreatePost()
        makeLuaModel('ring', 'ring', 'ringTexture', 600, 300)
        addLuaSprite('ring', false)
    end
    function onUpdate(elapsed)
        setProperty('ring.angleY', getProperty('ring.angleY') + elapsed * 90)
    end
The triangles are drawn from the farthest to the closest (there's no depth buffer), so models of up to a few thousand
triangles work best; very big models make the game slower. Faces with more than 3 corners are split into triangles.
